# Guard-R：候选可行性恢复（离线预研，2026-11-02）

**只回答一个问题**：

> 拒绝一个"预算违约的功率向量"，是否曾经使我们错过一个**可通过连续功率重优化恢复可行性**的更优通信配置？

**答案：是，但只有 3 次 / 200 块。** 而且**第二个种子也复现**（不像 Guard-v2 只有 Block 23）。
所以 Guard-R **没有被否证**，但它的支持量只有 3 个案例，**不能当性能结论**。

---

## 1 为什么这可能是新的（Phase A 源码事实）

| 事实 | 位置 |
|---|---|
| `bottleneck_sca` 只约束 **QoS 代理 + 功率箱**，**没有平均 EE 预算项** | `p3learn/bottleneck_power.py:280-288` |
| B/C 候选确实被重解（`bottleneck_sca`，失败退回 `dinkelbach`） | `allocation.py:1512-1526` |
| `maxmin_power_refine` 只在**已被采纳的拓扑**上跑（在 repair 阶段之前） | `allocation.py:1650-1660` |

**因此**：B/C 候选的功率是"瓶颈最优、但预算不可行"的点；
**现有实现从未在该配置下做过带预算约束的功率求解**。Guard-R 针对的缺口真实存在。

---

## 2 预登记规则（**不看真值**，两个种子同规则）

`B_swap_rx*` 或 `C_mode_*` 且：
1. 预测 QoS 通过（α=1.35 的 p05 口径）；
2. 候选自身**预测 min EE 相对执行动作改善 > 10%**；
3. **当前功率向量的预测平均 EE 违反 `(1−δ)η_ref`**。

做法：固定候选的通信对/方向/模式/端口**不变**，只重解全部活动链路的**连续电输入功率**，
调用 `maxmin_power_refine`（它只在**可行点**中保留最优，约束正是同一个 `(1−δ)η_ref` 与预测 QoS）。

**三条对照**（计算预算可比）：

| 组 | 做什么 |
|---|---|
| `original` | 归档的执行动作 |
| `same_topology` | 把**同等 refine 预算**用于原拓扑（检验"多算一点"本身有没有用） |
| `guard_r` | 把同等预算用于 B/C 候选的可行性恢复 |

## 3 结果（两个信道种子）

| | 设计种子 `2026102401` | 验证种子 `2026102801` |
|---|---:|---:|
| B/C 候选 | 162 | 166 |
| **命中预登记** | **31（25 块）** | **36（28 块）** |
| 恢复后预测可行 | **3 / 31** | **4 / 36** |
| 其中预测 min EE 优于执行动作 | 3 | 3 |
| **真值预算也通过** | **1** | **2** |
| 真值 QoS 违约 | 0 | 0 |
| `same_topology` 改变动作 | **0 / 31** | **0 / 36** |
| 命中候选的预测预算缺口（中位） | −145.4 M | −97.9 M |
| 缺口最小 / 最大 | −2.04 / −306.3 M | −9.89 / −349.2 M |

### 3.1 通过真值预算的三个案例

| 种子 | 块 | 候选 | 预测 min EE | 真值 min EE | 真值均 EE | 真值预算 |
|---|---:|---|---:|---:|---:|---|
| 设计 | 23 | `B_swap_rx_1` | 44.52 → 195.91 M | 44.97 → **197.85 M（+340%）** | 603.60 → 561.70 M（−6.9%） | ✅ |
| 验证 | 12 | `C_mode_RF` | 42.66 → 212.90 M | 45.74 → **232.09 M（+407%）** | 407.18 → 380.31 M（−6.6%） | ✅ |
| 验证 | 46 | `C_mode_RF` | 185.22 → 306.66 M | 198.63 → **310.52 M（+56%）** | 588.09 → 499.81 M（−15.0%） | ✅ |

**恢复是"真恢复"不是"勉强过界"**：三例的预测预算余量分别从 −2.04 / −9.89 / −29.68 M
变成 **+6.50 / +9.25 / +0.22 M**，同时**预测 min EE 都上升**（不是用 min EE 换预算）。

### 3.2 失败的两个案例（必须报）

| 种子 | 块 | 候选 | 恢复后预测余量 | 结果 |
|---|---:|---|---:|---|
| 设计 | 48 | `C_mode_RF` | **+0.00 M** | 真值预算**违约** |
| 设计 | 53 | `B_swap_rx_1` | +2.38 M | 真值预算**违约** |
| 验证 | 6 | `B_swap_rx_0` | **+0.00 M** | 真值预算**违约** |

**规律很清楚**：恢复点**恰好贴在预算边界**（+0.00 M）时，真值上大约一半会破。
这与"预算余量的预测误差 sd ≈ 2.8% η_ref"完全一致——**边界上的点是不可靠的**。
三例成功的余量是 +6.50 / +9.25 M（0.7%–1.5% η_ref）。

### 3.3 剩下的 27 / 31 个为什么恢复不了

命中候选的预测预算缺口**中位 −145 M（约 24% η_ref）**，最大 −306 M。
连续功率重解**改变不了量级**——`maxmin_power_refine` 在绝大多数情形直接返回输入动作
（margin 前后一模一样，例如 block 2 的 −50.62 M → −50.62 M）。

**所以可恢复的是"贴边"候选，不是"大幅违约"候选。** 这在 100 块里只有 1–2 个。

## 4 判决

| ai2 预登记的停止条件 | 是否触发 |
|---|---|
| 固定新配置后几乎找不到可行改进功率解 | **未触发**（3+4/31+36 找到可行，3 例真值也成立） |
| 收益基本只来自 Block 23，第二个种子无可重复改进 | **未触发**（验证种子有 2 个独立案例，且不是 Block 23） |
| 与同等计算预算的原拓扑精修相比没有优势 | **未触发**（`same_topology` 0/67 改变动作） |
| 真值预算违约明显恶化 / 时间成本过高 | **未触发**（真值预算违约 0/3；每候选约 900 次评价调用） |

**结论：Guard-R 通过预登记的四条停止条件，可以继续。**

但必须同时写在论文里的是：

1. **支持量是 3 / 200 块**（0.15%），**不能写"该方法显著提升最弱链路能效"**；
2. 三例都牺牲了均 EE（−6.6% ~ −15.0%），**这是 δ 预算内的合法权衡，但要如实报**；
3. 恢复只在**预算缺口 ≤ ~1.5% η_ref** 时有效（3 例余量 +0.22 ~ +9.25 M），
   缺口中位 24% 的候选**一律恢复不了**；
4. 贴边（+0.00 M）的恢复点**真值上不可靠**（2/3 破），需要额外的余量门槛——本轮未定。

## 5 没有建立的东西

1. **不是新算法**：只是离线可行性研究，`code/` 未改，`source_sha256` 未变。
2. **两个种子都已用于诊断**，所以这是"已有数据上的可行性证据"，**不是盲验证**。
3. 尚未做**第三个未参与选规则的种子**验证——按 ai2 的协议，若要主张收益，必须先冻结
   预登记规则与优化预算，再用新种子验证。
4. 未做 50 车、未换 SUMO 轨迹。
5. `maxmin_power_refine` 用的是 `solver="nm"`（默认），与主算法 `sca` 起点不同；本轮未对比。

## 7 一句话给复审方

> Guard-R 与 Guard-v2 有本质区别：它**不放宽预算**，而是**在固定新配置下重解连续功率**。
