# Feasible-first 联合优化 + 可行性探针 + 解析上界剪枝（2026-11-02）

**回答两个问题：**

1. 上一轮 Guard-R 的四处审计缺陷已纠正（等预算控制、动作变化判据、双预算口径、可追溯记录）。
2. **"为什么要先生成不可行解再修复？能不能从可行解出发？"** —— 有了确定答案。

**一句话结论**：

> 改顺序**不能**创造新的可行配置（可行配置是配置本身的属性，3–4 个）；
> 那 28 个候选**结构上不可满足预算**（最小化违反量后仍差 12.6% 中位）。
> 真正该做的是**在候选进池前用必要条件剪掉**：解析上界可**无损剪掉 9/31**，
> 剩下 19 个需要数值探针。

## 3 可行性探针：那 28 个到底可不可行

**方法**：对每个候选配置，直接**最小化归一化预算违反量**
（5 个起点：候选自身、映射值、几何中点、下界、上界；SLSQP；目标含 QoS 罚项）。

| 量 | 设计种子 |
|---|---:|
| 最小化后**仍不可行** | **28 / 31** |
| **可达的最小预算违反量** | **中位 12.65%，最大 26.11%** |
| 可达的最小 QoS 违反量 | 中位 **0.000%**（QoS 从不是瓶颈） |
| 可行（≤1e-6） | 3 |

**结论**：这 28 个配置**在给定 QoS 与功率箱下预算不可满足**（数值证据）。
注意：即使把 min EE 从 133 M 让到 98 M（块 2），平均 EE 仍差 5.4%。

> **措辞纪律**：SLSQP 是局部求解器，所以严格说法是
> "**在当前数值流程下未找到可行点，且可达的最小违反量仍为 12.6% 中位**"。
> 不能写成"已证明数学不可行"。

## 4 解析上界剪枝：一个可用的必要条件

**构造**：固定配置 m，逐链路取自身功率上能效峰值、**他人压到功率下界**（干扰最小）：

$$U_k(m)=\max_{p_k}\ \frac{r_k(p_k;\ \text{others}=lo)}{P_{c,k}+p_k},\qquad U(m)=\frac1K\sum_k U_k(m)$$

因他人功率只增不减干扰，故对**任意** $\mathbf p$ 有 $\mathrm{meanEE}(m,\mathbf p)\le U(m)$。
**若 $U(m)<(1-\delta)\eta_{\rm ref}$，配置一定不可行。**

| 量 | 设计种子（31 候选） |
|---|---:|
| 剪掉 | **9 / 31** |
| **误剪（真可行却剪掉）** | **0** |
| 漏剪 | 19 |
| **剪枝精度 / 可行配置保留率** | **100% / 100%** |

**价值**：这是一个**严格必要条件**，不需要预测评估器、不需要优化，
可以**无损**剪掉 29% 的结构不可行候选。但它偏松——另 19 个的上界高于阈值（余量中位 +8.1%），
必须用 SLSQP 探针才能判定。

## 5 对"为什么先生成再修复"的回答

| 假设 | 证据 | 判定 |
|---|---|---|
| 顺序改了就能救回更多配置 | 四种 arm 找到**同一组**可行配置（3 / 4 个） | ❌ 否证 |
| 那 28 个只是求解器没找到 | 最小化违反量后仍差 **12.65% 中位** | ❌ 否证 |
| 从参考解映射功率 = 可行起点 | 映射后仅 **2/31** 预算可行、13/31 QoS 通过 | ❌ 否证 |
| 生成器缺一个"配置可行性"预筛 | 解析上界**无损剪掉 9/31**（100% 精度） | ✅ **成立** |

**所以正确的做法不是"换顺序"，而是"进池前剪枝"**：

```
候选生成（离散配置 m）
        ↓
[新] 解析上界 U(m) < (1−δ)η_ref ?  ── 是 → 直接否决该配置（成本≈0，无损）
        ↓ 否
[新] 数值可行性探针（SLSQP 最小违反量）  ── 最小违反量 > 0 → 否决（成本 ~8 s/个）
        ↓ 可行
带预算约束的瓶颈优化（从可行点出发）→ 采纳
```

这样"修复"和"守卫"就都不再需要了——**问题在生成阶段被消灭，而不是在末尾被拦截**。

## 6 边界与未建立的东西

1. **不是新算法**：`code/` 未改，`source_sha256` 未变；全部是离线分析。
2. **两个种子都已被用于诊断**，本轮是"已有数据上的证据"，**不是盲验证**。
3. 可行性探针是**局部**求解：`min_violation > 0` 不能写成"数学不可行"。
4. 解析上界**偏松**（只剪 9/31）。更紧的界（例如把他人功率固定在某个内点并迭代）未探索。
5. 探针成本约 **8 s/候选**（SLSQP 5 起点 × ~400 评价），**远慢于在线要求**；
   若要工程化，必须换成更紧的解析界或更少的起点。
6. 未做 50 车、未换轨迹。

## 7 一句话给复审方

> 你问的"为什么不从可行解出发"，答案分三层：
> ① **改顺序不创造新可行配置**（四臂同解）；
> ② **那 28 个结构上不可行**（最小违反量 12.6% 中位，QoS 从不违约）；
> ③ **真正缺的是候选进池前的可行性预筛**——解析必要条件可无损剪掉 9/31，
> 剩下 19 个必须用数值探针（~8 s/个）。
> 所以 Guard-R 的正确归宿不是"更聪明的守卫"，而是**把这个检查前移成候选筛选**。
