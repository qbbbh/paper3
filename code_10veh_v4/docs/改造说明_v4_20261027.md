## 1. 为什么要新开一棵树

E4 要比较四组：

|  | 不加最低 EE 保障 | 加最低 EE 保障 |
|---|---|---|
| 均值 QoS | A：`--methods reference` | B：`--methods reference maxmin` |
| 机会 QoS | C：`--methods reference` + `--qos-metric chance` | D：`--methods reference maxmin` + `--qos-metric chance` |

v3 里 B/D 跑不了，有两处硬障碍：

1. `run_allocation.py` 的守卫写死：`--q-min-bps > 0` 时 `--methods` 只能是 `["reference"]`。
2. 去掉守卫也不对：`max_min_allocate` 调 `pure_ee_reference` 时没传 `q_min_bps`/`qos_metric`，
   `protect_budget` 也只守平均 EE 预算、不查 QoS。结果 D 组会选出一个提高最低 EE
   但把某条链路预测 p05 压到 1 Mbit/s 以下的动作，四组对照就不成立。

改这些会改变 `source_sha256`，所以按仓库惯例另起 v4，v3 原样保留。

## 3. 组 B/D 的判定规则

```
候选动作可行 ⇔ ① 预测均逐链路 EE ≥ (1-δ)·reference.eta_ref
             ② 预测 QoS 变量 ≥ 1 Mbit/s（逐链路）
```
只有两条都满足、且最低 EE 严格更高，才会替换 reference；否则显式记
`fallback=True`、`reason=reference_fallback_no_better_feasible_action`。

`qos_violation_links` 记的是**候选动作**的违约链路数（不是执行结果的），
`None` 表示这条记录没做 QoS 复核（即 A/C 组的 reference 行）。

## 4. 冒烟结果（3 块，draws=16，仅为接线验证）

| 组 | 块 | 决策 | 最低 EE (bit/J) | 均逐链路 EE | QoS 违约链路 |
|---|---|---|---|---|---|
| B | 2 | maxmin | 36.71e6 | 502.57e6 | 0 |
| B | 2 | reference | 16.25e6 | 552.37e6 | — |
| B | 3–4 | reference（maxmin 回退） | 19.52e6 / 46.77e6 | 637.71e6 / 668.38e6 | 0 |
| D | 2–4 | 与 B 逐位相同 | — | — | 0 |

块 2 上 maxmin 用 −9.0% 的均 EE（δ=0.1 内）换到最低 EE +126%。

**这 3 块里 B 与 D 完全相同，不是 bug**：选中的 15 条链路预测 p05 最小为
1.298e6 bit/s，全部高于 1 Mbit/s，机会约束在这几块不活跃，所以 mean 与 chance
给出同一个动作。这与协议 §4 的 P0 结论一致（违约只发生在 ρ<2 的贴边链路）。
**3 块不能当作 E4 的结论**，四组各 100 块才算。

## 7. 2026-10-28：再平衡打分修正 + 连续功率 Max-Min

### 7.1 再平衡候选的打分口径

`max_min_allocate` 生成的第四个候选（把"较强"链路降到 0.25 倍功率）原来用
$R/p$ 判强弱，与目标的 $R/(P_c+p)$ 不是同一个分母。已抽成 `rebalance_proposal()`
并改为电气分母，附回归测试（VLC 的 $R/p$ 与 RF 持平、但 $R/(P_c+p)$ 更高时
必须降 VLC）。

**它不是"先砍 VLC"**：逐块查下来，修正前被降功率的全是 RF 链路。真实机制是
$R/p$ 把功率放在分母，**功率越大得分越低**，所以高功率链路被放过；改成
$R/(P_c+p)$ 后静态功耗把差距压平，高功率链路不再被放过。结果是采纳块数变少、
但每块改动的链路更多。

### 7.2 连续功率 Max-Min

新增 `maxmin_power_refine()` 与 `--maxmin-power-refine`：固定匹配，log 功率空间
Nelder-Mead 最大化块内最低逐链路 EE，约束为同一个 `(1-δ)` 预算、同一套 QoS 变量、
`[1 mW, 2 W]`；结果仍走 `protect_budget` 复验。单块约 +3–5 s。

三块冒烟（δ=0.05，均值口径）：块 2 从"无可采纳候选"变成"最低 EE 16.3 → 69.2 M"，
L1 RF 功率 1 mW → 4.1 mW；块 3/4 仍回退——最弱链路是已达 2 W 上限的 VLC 链路，
功率层无解。块 2 真值均 EE 损失 5.25%，超过 5% 的预测预算 0.25 个百分点。
