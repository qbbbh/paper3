# 候选评价与联合算法

状态：确定性实现已落盘；有效性以实验报告为准，不预先认定优于普通搜索。公式对应 `src/cost.py`、`src/scheduler.py`，连续层仍是 `src/power.py` 的 direct/SLSQP。

## A1：共同问题和连续层

每个决策由已执行的9步服务算原始需求 d_i=[10q_i−Σ历史速率]_+，Mbit/s。Model.need 对活动发送者乘既有1+κ·rel_sd。没有被调度的正需求仍计缺口。累计预测能效为 (历史Mbit+0.01Σr)/(历史J+0.01Σp)，不是逐链路EE之和。

所有新臂共用B：先局部最小功率准备；必要时最小缺口回退；保留该分量服务底线，再从最多两个可行初始点局部优化原累计EE。maxiter=35、rounds=5、配置预算=6，不加新求解器。求解器失败或局部缺口不能当作配置全局不可行。保护缺口优先、其后EE改善的原接受规则不变；原始/保护缺口现在分别记录。

## A2：低成本服务探针

对合法完整配置m，把其他功率固定，定义T_i(p_−i)为当前10细样本平均预测速率达到活动需求的最小本链路功率。理论无帽精确T及其条件见03；实现采用帽区间内22次向量二分，从零执行3轮，同时更新各行。若帽内根未找到，只记录 `cap_root_not_found`，不发不可行证书，不剪枝。

实际探针有三个必须区分的近似：有限3轮、有限22次二分、功率帽截断。因此它不是已认证的最小服务功率，也不是理论单调迭代的严格数值下界。零需求链路保留cap×10^-5的EE探针，供比较额外服务；这不是在线最低功率约束，B仍可取零。

由探针得到全车速率r、功率p，评分按以下字典序升序：

1. 全部需求的保护缺口Σ[保护需求−r]_+；
2. 负的同一累计EE代理；
3. 总探针功率；
4. 规范配置编号，作确定性平局处理。

最小功率成本仅用于产生候选探针，不替代EE。有限探针残差较大时仍只能称排序启发。配置经排序后必须重解全网功率，最终接受不依据预测分数。

## A3：相同规则的消融

| 臂 | A的候选顺序 | B的信道/约束 |
|---|---|---|
| C4 | 保留历史LNS及原3轮倍率探针 | 原分位模型 |
| D0 | 共同候选短名单的字典顺序 | 原分位模型 |
| D1 | SHA256(固定种子20261016、决策编号、配置)顺序 | 原分位模型 |
| DI | 条件均值增益、完整同模式干扰的成本探针 | 原分位模型 |
| DU | 分位增益、去交叉干扰但保留自身散粒项的成本探针 | 原分位模型 |
| DJ | 分位增益、完整同模式干扰的联合成本探针 | 原分位模型 |

DI/DU只消融**A中第二阶段评分**的信息。共同catalog、前16孤立候选、至多32配置的初步截取及最终B仍使用原分位模型。因此DI是“第二阶段均值／干扰评分”，不能称整个算法忽略不确定性；DU也不是整个流程忽略干扰。当前κ=0；若以后κ>0，DI还保留Model.need中的rel_sd裕量。

各新臂使用相同C4确定性destroy/repair规则：删1/2条边、从共同前16孤立候选插入、按共同顺序修复，再以孤立覆盖需求和成本截取最多32个完整配置。同一冻结输入下短名单逐项相同；各自长期闭环的历史／previous会改变，不能声称全程每步候选集合相同。该短名单可能漏掉优质配置，任何实验保证均不覆盖短名单之外。

共同求解贪心起点和合法上一步配置。当剩余预算至少2时，留一个位置给按决策编号轮转的字典序候选，用于减少只检查高评分候选的偏差。公共起点、previous、排序候选和审计都计入**6配置总预算**，不是额外增加审计求解。其他位置按各臂顺序使用。所有D臂采用相同审计规则，C4按原实现保留；因此相同预算的主因果对照是DJ对D0/D1，而非仅对C4。若短名单耗尽，实际求解次数可能少于预算，应报告实际配置数和NLP调用数。

## A4：伪代码

```text
保留原始需求d，构造共同贪心起点及上一步配置

在剩余配置预算内，对候选重解全网功率
按原保护缺口/累计EE规则接受，独立复验Model.rates与合法性
在真实环境执行；真实速率只在执行后更新服务历史和累计目标
```

在线cost模块不导入Environment，不接受未来真值。新增 `conditional.py` 只从公开后验抽取保留时间相关性的条件路径；它用于另行标记的服务校准实验，当前DJ和B尚未采用真实周期服务分位数。这项实现差额必须保留。

## A5：复杂度及保证

设细样本数S=10、活动链路L≤floor(N/2)、短名单K≤32、轮数I=3、二分次数H=22。每配置构建系数与干扰背景O(SL²)，二分O(IHSL)，评分总成本O(K·I·(SL²+HSL))，再加预算Q≤6次非凸连续优化。日志另报连续调用数及实测耗时。无10ms实时性、混合全局最优或真实窗口联合可靠性保证。

固定快照、共同B下，已找到候选按接受规则单调改善“缺口优先/EE其次”的有限比较序。但每次只进行有限邻域，不等于收敛到全局最优；闭环目标受新观测、历史和几何改变，也不能由一次局部单调性推出全程EE单调。原始窗口QoS仍由独立实际物理审计判断。

## A6：冻结排序数字与已经核实的边界

开发60及seed20261017留出18快照均共享各自C4真实历史。独立审查重建78/78共同候选池与390/390条D访问序列，轮转审计全部在预算内实际执行。两批当前源哈希一致，详见《附录_独立一致性审查》。

DJ新候选top1/3/6命中为开发47/60、59/60、60/60，留出13/18、17/18、17/18。这里top-k仅排序fresh新候选；在线6总预算含1—2公共起点与审计，**top6不是在线可评6个新候选或找到最佳的保证**。

收益符号比较为开发622个候选、假阳性166／假阴性2，留出192个、52／13；可行性门控检查的是公共配置和候选的B100强参考解，不是probe自身已经可行。漏检也是共同有限池内的配置访问指标，强参考为局部解，缺口改善与可行EE改善不能混称。

DJ与C4在全部78个快照中配置、功率、实际速率、能量和同历史累计EE逐项完全相同；DI只有开发2个无服务意义的数值配置差异，留出18个完全相同。因此当前可以报告DJ相对字典／哈希顺序少漏访，不能宣称相对原C4的条件决策收益或联合不确定性评分已显示独立价值。同配置预算不等于同NLP次数或同耗时；闭环收益以随后完成的留出结果为准。
