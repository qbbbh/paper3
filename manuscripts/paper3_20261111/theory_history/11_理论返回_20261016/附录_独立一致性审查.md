# 独立一致性审查：候选预算、审计保留与冻结排序结果

审查日期：2026-10-16。范围：冻结的src/cost.py、src/scheduler.py及共同连续层接口；开发seed20261014的60个冻结快照和seed20261017的18个快照。本审查没有修改src、frozen、冻结参数、旧数据或已有结果，也没有重启／重优化长闭环。核查采用保存的公开belief、真实过去服务、决策前状态和原始逐快照JSON，在内存重建候选与统计，不用新增低价值测试扩大覆盖。

**结论：在这78个保存快照和当前6配置预算下，没有发现候选池、访问预算、轮转审计或汇总数字的实质一致性缺陷；当前源码哈希与两批冻结清单完全一致。DJ与C4在78个快照中最终配置、功率、实际速率、能量和同历史累计EE逐项完全相同，不能据此声称联合评分产生了相对C4的条件决策收益。**

## 1. 证据与审查方法

主要证据：

- 独立开发目录src/cost.py、src/scheduler.py、src/model.py、src/power.py。
- results/frozen_ranking/plan.json、summary.json、60个n*_q*_k*.json及snapshots内公开belief／历史／决策前状态。
- results/frozen_ranking_holdout17/相同结构的18个快照。
- analysis/frozen_ranking.py，以及交付成果中的两个《冻结快照排序验证》附录。
- results/p0_archive_compare_after.json、p0_baseline_after.json和旧不确定性感知目录中的C4源码。

独立重建步骤：

1. 由每个保存历史重新计算全部车辆原始需求，核对history长度、k和decision_index相等。
2. 重建catalog孤立功率／帽速率、前16条边、destroy–repair完整候选、共同孤立规则截取的至多32配置，并排除公共缓存。
3. 比较DI／DU／DJ保存的全部评分候选集合；D0／D1虽不存score_details，其访问序列按相同重建候选池分别重算。
4. 重建各D臂的排序、预算内轮转审计插入和实际访问序列；对C4重新计算旧倍率proxy的访问顺序。
5. 不重新求解连续B，使用保存的逐配置强参考，重新计算top-k、收益符号、访问配置漏检、实际有服务动作改变、全需求覆盖及汇总。
6. 核对每个实际动作能量等于0.01乘总功率；计算当前src／frozen全部9个Python源文件哈希，并与两批冻结清单逐项比较。

这是对冻结输入、实现路径与已保存数值的独立一致性审查，不把保存的局部解升级为全局解，也不构成额外交通轨迹或独立统计重复。

## 2. 候选池与预算公平性

### 2.1 实现上共同的部分

各D臂在固定同一输入状态时，先共用贪心修复起点及合法上一步配置，调用相同Model与direct/SLSQP。随后从共同当前最佳公共起点生成一次确定性destroy–repair邻域，按共同孤立覆盖／功率规则截取至多32个新配置，只有第二阶段排序规则随D臂改变。

evaluate通过配置规范化和cache保证同一配置在同一决策最多求解一次；len(cache)达到budget后不继续调用B。公共起点、previous和审计均计入6配置总预算，审计不是额外第7次求解。B未读取A的探针功率作特权初值；相同配置、信息、目标、历史及参数传入同一连续求解规则。

| 检查项 | seed20261014 | seed20261017 |
|---|---:|---:|
| 保存快照 | 60 | 18 |
| 公共起点配置、功率、EE和缺口逐项相同的快照 | 60/60 | 18/18 |
| DI／DU／DJ完整新候选集合等于独立重建池 | 60/60 | 18/18 |
| D0／D1／DI／DU／DJ实际访问顺序等于独立重建 | 300/300 | 90/90 |
| 六臂实际求解配置数恰为6 | 360/360 | 108/108 |
| 任何访问配置超出共同候选加公共起点 | 0 | 0 |
| history长度／k／decision_index一致 | 60/60 | 18/18 |

这里“共同候选池”有明确条件：冻结实验把各臂置于同一C4历史和同一previous。各臂自己的长期闭环会产生不同历史与previous，进而改变需求、起点和候选池；长期实验只能声称使用相同生成规则和预算，不能声称每一步候选集合逐项相同。

### 2.2 同配置预算不是同计算成本

连续层采用共同准备与最多两个可行初值，但所选配置不同，是否发生缺口准备、第二初值是否可用和SLSQP迭代数会不同。因此相同6配置预算不等于相同NLP调用数、函数评价数或耗时。

开发60快照中D0、D1、DI、DU、DJ的平均NLP调用数分别为18.45、18.4167、18.15、18.15、18.15；对应平均时间108.97、107.20、156.25、154.73、155.00ms。留出18快照中分别为18.6667、18.5、18.0556、18.0556、18.0556。报告已列这些数值，支持“同配置预算下排序比较”，不支持“相同计算量”或“实时性已达成”。

## 3. 轮转审计是否真的保留

propose先对共同fresh候选按配置编号排序，以decision_index取模选择audit_cfg。当剩余预算至少2时，保留至多remaining−1个评分候选并将audit_cfg置于最后；若它已经位于评分优先候选中，先去重再插回。

在本实验budget=6且公共配置至多2个的条件下，只要存在fresh候选，剩余预算足够执行该规则。独立重建确认全部390条D方法快照访问中，审计候选都实际被评价，未被提前预算终止丢弃。开发300次中有81次审计本来已在自然前预算候选中；留出90次中有30次如此。其余情况确实占用一次本来可给其他评分候选的预算。

边界：

- 一般参数下remaining<2、fresh为空时，没有同样审计保证；不能将本结果推广为任意budget必有审计。
- 编号轮转是确定性覆盖机制，不是从候选均匀随机抽样，更不构成统计无偏审计或风险认证。
- C4保留旧排序，不参加D臂的轮转预留。因此DJ对D0／D1是隔离第二阶段排序影响的主要对照；DJ对C4同时包含旧／新proxy与审计预留差异，不能只归因为不确定性评分。

## 5. cost探针及消融主张边界

### 5.1 实现与理论固定点没有混同

service_probe从零执行3轮同步更新，每轮22次帽内二分。无法在帽内求根只记cap_root_not_found与服务缺口，不剪枝；保存字段certified=false。最终零目标边的cap×10^-5只供EE探针，未作为B功率下限。target在构造保护需求时复制，DI均值替换也仅修改浅拷贝字典的新键，DU清零的是新Model数组；没有发现污染共享belief或其他臂的写入。

但有限帽截断、二分上端和3轮干扰传播既不保证固定点收敛，也不是严格成本下界。某个配置的probeEE低，不能证明它经完整B后的最优EE低。现文档使用“排序启发、非认证界、不剪枝”与实现一致。

### 5.2 消融只发生在排序阶段

DI在cost模型中把低／高增益替换为均值，DU移除交叉平方干扰与交叉散粒项但保留自身散粒。共同catalog、前16边、32配置截取和最终B仍使用原分位模型。

因此可以写“第二阶段候选排序中的干扰／不确定性信息消融”，不能写成“整个算法完全忽略不确定性／干扰”。当前κ=0不产生额外裕量混杂；若以后κ>0，DI仍保留Model.need中的rel_sd裕量，须再限定其含义。

此外，probe评分按浮点原始缺口严格排序，而最终better在总缺口1e-6Mbit/s（1bit/s）内转比EE。两阶段数值优先级并不完全相同；极小probe残差可能压过EE。这是冻结启发的近似边界，不能未经反事实就认定为本轮无收益的因果原因，也不应在留出进行中修改规则。

### 6.1 必须准确解释的三个分母

**top-k不是在线6预算的同义词。** 此指标只对fresh候选排序，判断前k中是否包含与全fresh强参考最佳等效或更好的候选，等效按better容差判定。在线6总预算还要支付1—2个公共配置以及轮转审计，未必可以评价6个新评分候选。top6=100%不能改写为“在线预算6保证找到最佳新候选”。

**符号比较的可行门控针对强参考功率解。** 代码检查B100公共配置解和候选配置解的deficit≤1e-6，再比较两配置probeEE变化符号与强参考EE变化符号；它没有要求probe自身已经满足服务。622／192应写成“强参考可行配置中的probe收益符号比较”，不能写成“probe可行动作已获收益保证”。假阳性／假阴性原始数也不能直接当precision／recall，其各自条件分母未在该汇总中列出。

**漏检是共同有限池的配置访问指标。** 每个被访问配置重新用统一B100局部参考值评价，再与整个共同候选加公共起点池最佳比较，目的是隔离访问集合选择。它不衡量短名单之外的漏检，也不证明强参考全局最优，不等于实际执行EE后悔值。若参考仍有缺口，better可能因为较小缺口而判优；不能把所有漏检计数叫作“丢失更高可行EE”。

当前两份排序附录大体遵守上述边界。建议定稿继续采用明确表述：“在固定C4历史的共同有限候选池中，DJ减少了相对字典／哈希顺序的配置漏访，但与原C4及仅均值／干扰评分没有有服务意义的最终动作差异；评分开销增加，独立闭环效益尚需完成验证。”

此表述不会否定E4–E8／S1–S3的条件数学结果；它只说明已完成的排序数据尚未把这些结构转化为新增算法收益。没有发现需要破坏当前sourcefreeze修复的真实实现缺陷，长闭环可按已冻结方案继续，后续负结果也应完整写入。
