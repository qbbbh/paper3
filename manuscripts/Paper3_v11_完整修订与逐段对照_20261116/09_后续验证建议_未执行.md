# 后续验证建议：未执行

本轮修改使用已有冻结结果，没有增加算法、修改科研代码或启动仿真。以下两项是后续可选工作，分别补充已有结论的适用范围和业务需求变化下的表现；它们不是当前稿件中的已完成实验，也不预设结果趋势。

## 一、50车场景的导频到达时延验证

**要回答的问题。** 当前四档额外时延实验使用10车场景的第二次信道实现。补充50车实验可检查：在另一车辆规模及相应交通场景下，观测到达与决策时序如何改变信道预测、速率预测和资源分配。不能先假定时延一定降低能效，或VLC误差仍出现相同平台。

| 项目 | 可选方案 |
|---|---|
| 场景 | 50车既定路网的一次已冻结信道实现，优先与现有第二次实现及其时点集合对应 |
| 自变量 | 额外导频到达时延$\Delta d\in\{0,5,10,20\}$ ms |
| 决策时点 | 预先固定覆盖100 s的200个时点；估计器连续处理完整历史 |
| 保持不变 | 交通、真实信道、业务门限、导频功率与积分时长、功率范围、预测样本数、求解预算及$\delta$ |
| 重新计算 | 各档按到达条件形成可用观测，重新估计和预测，重新求第一阶段及公平分配；每档建立自己的参考EE |
| 评价 | 信道增益误差；固定零额外时延Mean-EE动作后的速率预测误差；重新优化后的实际平均EE、最低EE、服务表现、模式变化与RF/VLC使用比例 |
| 呈现 | 若开展，补入现有信息时延图的另一规模面板或紧凑附图，不额外复制整套主方法比较 |

零额外时延表示当前有噪观测设置。固定动作预测和重新优化应分别呈现：前者考察预测信息变化，后者考察算法对这些变化的响应。

## 二、最低业务速率要求的敏感性

**要回答的问题。** 当前方法比较采用$R_{\min}=1$ Mbit/s，实际服务达标率较高。更高业务需求下，功率、干扰与平均EE下降约束怎样共同限制最低EE改善，是与现有预算扫描不同的问题。

| 项目 | 可选方案 |
|---|---|
| 场景 | 10车和50车各采用一组既定信道实现，保持各自路网 |
| 自变量 | 拟议$R_{\min}\in\{1,5,10,20\}$ Mbit/s；正式运行前固定，不按结果选择有利档位 |
| 决策时点 | 沿用各规模预定的200个时点 |
| 最小方法阵容 | Mean-EE、PF-EERA、Fixed-Mode |
| 保持不变 | 信道信息、真实信道、导频设置、功率范围、条件轨迹数量、求解预算及$\delta=0.10$ |
| 重新计算 | 每个新需求重新求第一阶段和该需求下的参考EE，再运行公平阶段；不能只用旧动作检查新门限 |
| 评价 | 全部计划周期上的返回分配比例与实际服务达标率；相同可比时段的平均EE、最低EE及效率代价；RF/VLC使用与功率变化 |
| 作用 | 判断提高业务要求后公平改善如何变化，并检查模式调整是否在更严格的服务要求下产生不同作用 |

既有1 Mbit/s结果只有在模型、估计输入、预测样本及全部求解设置一致时才可直接复用。新增三个需求档、两种规模、每档200个时点对应1200个“状态—需求”组合，实际求解次数还取决于方法阵容；这里不把该数字当作运行时间估计。

## 选择顺序

若目的是补充当前时延解释在另一规模下的证据，优先第一项；若目的是扩展业务条件并观察资源选择规律，优先第二项。两项回答不同问题，无需为了图表数量同时展开。正式开展前固定配置、时点和输出，完成后按实际结果写作。本轮交付的摘要、正文、图件和结论均未使用这两项尚未执行的结果。
