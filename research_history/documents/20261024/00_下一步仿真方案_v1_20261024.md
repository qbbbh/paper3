## 1. 现在固定了什么、没固定什么

结论：**通信规则最扎实（有代码强制），优化目标只固定了方向，计分最弱（有指标、无判据）。**

| 维度 | 现状 | 证据 | 缺口 |
|---|---|---|---|
| 怎样通信 | 已固定，代码强制 | 100 ms 一块；每车恰好出现一次，共 N/2 条有向链路；块内模式/功率/端口冻结；未选边功率 0；禁块内重配、提前停止、跨块补偿。`p3base/block.py` 的 `validate_action`/`summarize_block` 会拒绝不完整覆盖 | 导频与数据如何共享时间/带宽仍未定（入口文档自己写了"尚须明确"） |
| 优化什么 | 方向固定，参数未批准 | `max η_min s.t. ΣR − (1−δ)·η_ref·ΣP ≥ 0`，实现于 `p3learn/allocation.py` | δ=0.05 是代码默认，不是文档批准的取舍；`η_min` 的业务含义（块级、跨块关系、参考是谁）未形式化 |
| 怎样计分 | 指标齐、判据无 | network EE、min pair EE（失败记 0）、failure/fallback rate、budget violation rate，且有独立审计脚本 | 没有预注册的主端点/次端点，没有"什么算支持假设、什么算否定"，没有种子数、块数、配对统计方案 |

两处已经核实、需要写进规格的事实：

- **能量口径**：`p3base/block.py:109` 里 `energy = duration * p`，只计数据发射功率；导频与电路能耗不计入。这是范围选择，必须在论文中声明，不能默认它等价于整机能耗。
- **η_ref 是预测值**：预算门用的是同块 reference 动作在条件轨迹预测下的网络 EE（`allocation.py` 里 `reference.eta_ref`），不是真值。审计脚本会另外核对 reference 的预测与真值，两者不能混用。

## 2. 现方案的不足（按能不能毁掉结论排序）

1. **回退率 100%，policy 从未真正执行过。** 50/100 车三次短跑全部 `fallback_rate=1.0`，策略结果其实是 reference 的结果。在这个前提下比较 `mlp` / `hetero_graph` / `hetero_graph_v2` 没有意义。而且 2 块训练本来就学不到东西——**用未训练的策略评判架构，是协议错误，不是实验结果。**
2. **硬回退门造成训练与部署不一致。** 提议被整体换回 reference，actor 拿不到"我这个动作差在哪"的信号，critic 看到的执行动作也不是策略采样的动作，循环会自我强化。需要先确认训练期是软惩罚还是硬门，以及回退时 (proposal, executed) 是否都记录、回报记给谁。
3. **max-min 目标的训练信号极稀疏。** 只有一条链路决定回报。需要显式决定：先学网络 EE 再逐步收紧，还是用 soft-min / 低分位近似。这是目标设计决策，必须写进规格，不能边训边换。
4. **credit 只诊断、不进训练，且 48 条截断有选择偏差。** "问题在提议质量、不在动作空间"这句话超出单块 48 个替换能支持的范围，应改成"在这些块的这些候选里"。
5. **单块、单种子、draws=4。** 50 车块 4 与块 5 的参考网络 EE 差 8%（1.875e10 vs 2.029e10），块间波动大于任何算法差异。
6. **异构图没有可证伪假设与同预算消融。** 30 dB 窗口、VLC 端口代理都是建模选择；v2 只改变了预测值，执行结果逐位相同。
7. **审计只保证内部一致**（分母、方法集合、数组名），不保证物理正确。缺一个 2 车 1 块的手算 golden case。

## 3. 分阶段方案

原则：**先证明"策略能执行、能学"，再谈"哪种编码器更好"，最后才谈"主算法是否领先"。** 每阶段不通过就不进入下一阶段；任何阶段的中止都要保留结果与版本，不删不改。

| 阶段 | 做什么 | 产出 | 通过判据 | 停止规则 |
|---|---|---|---|---|
| **0 规格冻结** | 写 `SPEC_v1`（六项 + 目标 + δ + 计分端点 + 预注册判据）；做 2 车 1 块人工算例 | `SPEC_v1.md`、手算表 | 手算 SINR/速率/EE/预算与代码逐位一致；SPEC 能回答"这张表由哪套问题生成" | 对不上先修口径，不进入任何学习实验 |
| **1 回退诊断** | 固定 1–2 块与 reference 动作：把 reference 动作喂给 actor 算 log-prob 与候选内排名；检查被选边是否落在候选掩码内、增益与功率分布；用固定 critic 给 proposal 与 reference 打分 | 一页诊断表 + 图 | 能区分三类原因：训练/探索不足、输出头或掩码错误、critic 打分错误 | **不许调参、不许换编码器**；查清前不训练 |
| **2 能学会的最小证据** | 行为克隆到 reference（几十块即可），再小步 RL 微调 | 一致率曲线、EE 差距 | BC 在训练块上动作一致率 ≥ 90%；否则先修表征或动作头 | 不过就不进入 RL |
| **3 短程配对评估** | 5 seeds × 10 blocks，按块配对，报 median / IQR | 配对表 | 主端点：min pair EE 相对 reference 提升，bootstrap 95% CI 下界 > 0；约束：network EE 不低于 (1−δ)·reference；fallback ≤ 20% | fallback > 50% ⇒ 视为协议未成立，回阶段 1，不得调参 |
| **4 同预算消融** | `reference / maxmin / policy(mlp) / policy(hg v1) / policy(hg v2)`，同候选预算、同物理、同动作域；逐场景报代价 | 消融表 | 每个模块能说清"改善了哪个指标、付出什么代价" | 允许消融在某指标更好，不因此判主算法错 |
| **5 正式批次** | 50/100 车、多流量种子、独立测试集 | 正式结果 | 阶段 3、4 均已通过 | 未通过不启动长跑 |

阶段 0–2 都只需要几分钟到几十分钟，**不需要长跑**。阶段 1 的结论会直接决定要不要改动作头或掩码，改完再谈训练。

## 4. `SPEC_v1` 草案（待批准）

### 4.1 六个问题

| 项 | 当前值 | 状态 |
|---|---|---|
| 谁通信 | 每块 N 辆车全部参与；每辆恰好出现一次；共 N/2 条有向链路 | 已定，代码强制 |
| 块内能否改配置/停发 | 100 ms 一块，配置、模式、功率、端口整块冻结；未选边功率 0；禁块内重配、提前停止、跨块补偿 | 已定 |
| QoS 约束还是仅评价 | q=0；1 Mbit/s 只是描述性诊断线，不是门限 | 用户 2026-10-24 表示"QoS 不取消"；agent1 并未建议取消，取消是更早的用户决定。恢复需先定门限并公平施加于 reference / maxmin / policy，**待确认门限**。本轮学习链条验收仍按 q=0 跑，避免中途换题 |
| 比特与能量归属 | 每条有向链路计一次；网络 EE = Σ平均速率 / Σ功率；能量 = 时长 × 数据发射功率（不含导频、不含电路） | 已实现，但"不含导频"需在论文声明 |
| 公平对象与时间范围 | 块级最弱通信对 EE；块间独立，不做跨块累计或补偿 | 已定 |
| 决策可见信息 | 块初估计/信念、CSI 年龄、候选与业务掩码；不看未来真值 | 已定，代码无 oracle 入参 |

### 4.2 目标与计分

- 目标：`max η_min`，约束 `网络 EE ≥ (1−δ)·η_ref`；`η_ref` 为同块 reference 动作的**预测**网络 EE。
- **δ = 0.05（2026-10-24 定为开发值）**：用户明确"取值与依据无法给出，先固定 0.05，效果不好再调"。
  它决定"最低 EE 改善"能用多少网络 EE 去换，是研究取舍，不是超参数；论文里必须写成事先指定并做 δ 敏感性，
  不能在看到结果后选 δ。
- 主端点：配对后的 min pair EE 提升中位数。
- 约束端点：network EE 损失是否在 δ 内。
- 次端点：failure rate、fallback rate、budget violation rate、单块求解时间。
- 明令禁止：跨场景平均成"几乎免费"、选择性报告、用未训练策略的结果排架构。

### 4.3 预注册判据（草案，待批准）

- 支持：阶段 3 中主端点提升的 95% CI 下界 > 0，且 fallback ≤ 20%、无失败块。
- 否定：主端点 CI 跨 0，或 fallback > 50%。
- 否定后的动作：**回阶段 1 诊断，不调参、不换编码器、不换场景。**

## 5. 需要拍板的四件事

1. **δ 定多少、依据是什么？** **已定（2026-10-24）：** 开发期固定 0.05，效果不好再调；
   但要事先登记"调 δ 的判据"，否则又变成看结果调参。
2. **QoS 永久只做事后评价，还是恢复最低速率？** **仍未决。** agent1 没有要求取消；
   取消是更早的用户决定。用户 2026-10-24 表示倾向保留。若要恢复，必须①给出门限（是否 1 Mbit/s）
   ②对 reference / maxmin / policy 同时施加 ③写进 SPEC 并重跑基线，不能只对学习策略施加。
3. **回退算正常安全行为，还是必须接近 0？** 这决定验收标准，也决定要不要改训练期的门。
4. **100 车异构图是否作为论文贡献之一？** **已定（2026-10-24）：是贡献之一，但不是主要创新点。**
   仍需一个单独可证伪的假设（例如"同等训练预算下 min pair EE 更高"），而不是"加了异构图所以更好"。

## 6. 本轮不做

- 不启动长跑；不改训练期预算门的实现（等阶段 1 结论）。
- 不加 GRU、分布式风险 critic、完整 Shapley。
- QoS 门限未定，本轮不恢复硬约束；但 `q_eval_bps` 仍逐块报告，作为事后诊断。
- 不改 γ、不加业务队列或跨块补偿。
- 不改 10 车数值线；不改已有结果与交接包。
