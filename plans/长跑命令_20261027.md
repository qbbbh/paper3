# 两条满 100 s 长跑命令（2026-10-27）

对应 [仿真协议 v1](仿真协议_v1_20261027.md) §7 的"满长度运行"。目的只有一个：
把已有的 **100 块窗口（10 s）**对照扩到整条轨迹（99.8 s），看 `mean` 与
`chance α=1.35` 的差距在长窗口上是否还在。

---

## 1. 两条命令

在同一目录 `代码/开发_50_100车_v3_20261024/code` 下执行。

```powershell
# A：纯均值
python -B -I run_allocation.py --n 10 --delta 0.1 --phase evaluate --split development `
  --methods reference --blocks 998 --start-block 2 --draws 32 `
  --channel-seed 2026102401 --forecast-seed 2026102501 --learning-seed 2026102601 `
  --csi estimated --forecast-information trajectory `
  --power-solver continuous --reference-search joint --joint-rounds 8 `
  --qos-metric mean --qos-fallback-mean --qos-chance-rounds 2 --threads 2 `
  --out runs/n10_long_s1_joint_mean_20261027

# B：机会约束 α=1.35
python -B -I run_allocation.py --n 10 --delta 0.1 --phase evaluate --split development `
  --methods reference --blocks 998 --start-block 2 --draws 32 `
  --channel-seed 2026102401 --forecast-seed 2026102501 --learning-seed 2026102601 `
  --csi estimated --forecast-information trajectory `
  --power-solver continuous --reference-search joint --joint-rounds 8 `
  --qos-metric chance --qos-chance-inflation 1.35 --qos-fallback-mean --qos-chance-rounds 2 --threads 2 `
  --out runs/n10_long_s1_joint_chance135_20261027
```

A/B 只差 `--qos-metric` 与 `--qos-chance-inflation` 两项；其余必须逐字相同，
尤其是 `--channel-seed`、`--draws 32`、块范围与 `--joint-rounds 8`。

可执行版本见 `代码/交接_长跑与复现_20261027/`（`run_long_100s.ps1` +
`requirements.txt` + `README.md`）。

## 2. 覆盖范围

| 项 | 值 |
|---|---|
| 块编号 | 2–999（998 块） |
| 物理时间 | 0.2–100.0 s（99.8 s） |
| 轨迹来源 | `SUMO_* / n10 / mobility.npz`，1001 帧 × 0.1 s |
| 活动链路 | 5 条/块 → **计划** 4990 链路块/run（失败块另计，不能当成功执行数） |
| 预估耗时 | 75–90 min/run（单块 4.5–5.4 s），两条 2.5–3 h |

这是**同一条交通轨迹**上的长窗口，不是新增交通场景。跨场景仍只有已完成的
场景 B（SUMO seed 20261027，100 块）。

998 是**固定起点 2 时的物理可用块数**，不是代码检查出来的上限。范围守卫写的是
`start+blocks > len(time_s)`（`len=1001`），所以 `start=2, blocks=999` 会被放行、
请求到 100.1 s；当前 998 块的命令本身安全，差一块的检查待修。

起点取 2 而不是 0/1：`--start-block` 允许 ≥1，但块 0/1 的导频到达与初始化历史够不够
尚未诊断。要跑"整 1000 块"需要先补这个诊断并修范围检查，不是换个参数的事。

## 3. 跑完看什么

按 [仿真协议 v1](仿真协议_v1_20261027.md) §3 的指标报，至少包括：

| 指标 | 为什么 |
|---|---|
| 均逐链路 EE | 主目标 |
| 块内最低 EE（再对块平均） | 公平性，α=1.35 的主要收益面 |
| $V_{\mathrm{link}}$ 与实际违约链路块数 | 主约束口径，分母是 4990 |
| 有违约的块比例 | 与上一行分开报 |
| 全网平均电功率、VLC 占比、1 mW 贴地占比 | 每次报功率分配必备 |
| 回退块数（`chance_fallback=True`） | 不计入"约束通过" |

**重点不是复现 3/1500 这个数。** 1500 是**三个** 100 块 run 的合计（每个 500 条），
长跑是单 run 计划 4990 条；分母不同，违约数会变大，比例才是要看的。

要回答的是：违约是否仍然集中在 $\rho<2$ 的链路、比例是否仍停在 0.2% 附近。
这是**检验**该现象能否延续，不是假定它不变——后 90 s 的车流与遮挡关系不同，
出现新的远端点违约也是可能的结果。若长跑比例明显偏离 100 块窗口，说明 10 s
窗口抽样太窄，此前所有"0.2%"都要加窗口限定。

## 4. 已知的、不要在这两条里解决的问题

- 只有 A 场景、单条交通轨迹、单个信道种子。长跑不等于泛化。
- `α=1.35` 是在 A 场景 100 块上选的，这里用它跑 A 场景属于**同数据**，不是样本外验证。
  要谈"校准有效"，仍需要独立校准集（协议 §2.2）。
- §4 的"机会口径违约只发生在 $\rho<2$"是 10 s 窗口的观察；长跑是在**检验**它能否
  延续到 100 s，不是自动继承。均值口径本来就有 $\rho\ge2$ 的违约，见协议 §4 第 1 条。
- E4 四组消融（mean/chance × reference/maxmin）**不能**用这组命令跑：
  `--q-min-bps>0` 时 `--methods` 只允许 `reference`，且 `max_min_allocate` 未接
  QoS 约束。见 [仿真协议 v1](仿真协议_v1_20261027.md) §8。

主表仍用 100 块（三个种子有重复，长跑只有一个种子）；若不一致，先查抽样，
再决定主表用哪个窗口。
